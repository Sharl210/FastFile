# FastFile 3.0

FastFile 是一个面向个人与小团队的轻量传输系统。系统将文本、图片、视频、音频和普通文件统一纳入同一条会话流，兼顾即时发送、集中查看与轻量归档。

## 能力概览

- 文本与文件统一收敛到同一会话流
- 图片、视频、音频与长文本共用统一查看器
- 长文本默认摘要展示，按需进入全文查看
- 视频、音频、文本阅读进度可持续保存
- 上传支持多文件、断点续传、取消与后台任务面板
- 输入框支持桌面端拖拽文件上传与任意文件粘贴上传
- 登录密码支持逗号分隔多个值，每个密码对应独立用户

## 核心能力

### 统一查看器

- 图片、视频、音频和长文本复用统一查看器框架
- 支持上一条、下一条、关闭、键盘切换与复制等常用操作
- 标题统一显示文件名、类型与当前位置，降低切换成本

### 长文本处理

- 聊天流中仅展示长文本摘要，避免正文直接撑满主列表
- 进入全文查看后支持继续阅读、复制和条目切换
- 文本查看器保留自动换行、缩放和阅读进度等状态

### 上传与传输

- 支持图片、视频、音频和普通文件统一上传入口
- 输入框支持桌面端拖拽投放，松手即可直接进入上传队列
- 输入框支持粘贴任意文件，图片不再是唯一可直接粘贴的上传类型
- 上传分片可续传，任务可隐藏到后台继续执行
- 文件读取支持按需范围读取，降低媒体播放与下载时的无效开销

## 性能优化

### 前端渲染优化

- 聊天流采用局部渲染，只保留可视区附近的消息节点，远处内容改为占位撑高，降低长列表 DOM 压力
- 长文本查看器按视口附近分块渲染，滚过的内容会逐步回收，避免长文一次性铺满页面
- 输入框与全屏草稿编辑器对超长草稿和超大文本粘贴采用渐进式处理，优先保证主线程可用性，减少页面卡死风险
- 输入区拖拽上传带有明确投放态反馈，减少误操作；文件粘贴与拖拽共用同一上传队列，避免额外入口分叉

### 数据库与轮询优化

- 消息轮询引入修订号和 `ETag`，无变化时直接返回 `304`，减少重复查询与重复下发
- 数据初始化会补齐当前版本所需的用户归属字段，并将历史数据迁移到默认用户作用域
- SQLite 连接启用更适合并发读写的等待与日志模式，降低多人上传、轮询和读取同时发生时的锁冲突概率
- 上传分片写入与进度更新收敛到同一事务，减少多用户同时上传时的中间态抖动和进度错位
- 文件读取、消息轮询与上传写入按用户作用域并发执行，尽量避免多人同时使用时互相放大数据库压力

### 多用户隔离优化

- 每个密码映射为独立用户，聊天记录、界面状态、文本阅读进度和音视频播放进度彼此隔离
- 上传会话按用户维度作用域化，避免不同用户之间的断点续传状态相互污染
- 文件访问与消息读取均按当前用户权限过滤，降低串线和误读风险

## 使用方式

1. 打开页面并输入访问密码。
2. 直接发送文本，或通过上传入口选择图片、视频、音频和普通文件。
3. 桌面端可直接把文件拖到输入框区域，或在输入框中粘贴任意文件进入上传。
4. 点击缩略图、封面或“查看更多”进入统一查看器。
5. 在查看器中继续切换条目、查看内容或复制文本。

## 默认访问信息

- 地址：`http://127.0.0.1:21443`
- 登录密码需由部署方在 `fastfile.env` 或环境变量中显式设置

## 部署说明

### 本地运行

```bash
cargo run
```

### 生产构建

```bash
cargo build --release
```

发布产物默认位于：

```bash
target/release/fastfile
```

### 建议的生产部署方式

1. 将仓库放到固定目录，例如 `/opt/FastFile`
2. 在该目录内维护 `fastfile.env`
3. 将 `FASTFILE_STORAGE` 指向独立持久化目录，例如 `/data/fastfile`
4. 使用 systemd 托管 `target/release/fastfile`
5. 发布后通过 `/api/healthz` 和首页进行回归验证

## 适用场景

- 个人设备之间的临时传输
- 小团队内部资料中转
- 需要统一查看文本与多媒体内容的轻量场景
